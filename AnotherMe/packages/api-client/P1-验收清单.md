## 1. 范围回顾

让网关**自己拥有** HTTP 表面所需的类型 / DTO / 错误响应；运行时服务
（`get_book_engine` / `ChatOrchestrator` / `EditAgent`）仍然由 `tutor_engine`
提供，留到 P1.3-P1.5 增量迁出。

## 6. 关键设计决策

1. **类型 + 错误响应先迁，运行时服务后迁**：完整的「迁出」分 5 步走
   （P1.1-P1.5），本轮先固化**数据契约**与**错误契约**这两条最重要的边界，
   让 HTTP 表面与导师引擎的内部细节解耦。
2. **Fallback 模式而非 hot cut**：`contracts.py` 通过 `try/except` 让
   `internal.*` 优先、`tutor_engine.*` 兜底，运行时跑旧路径，编译时强制
   走新路径。CI 测试保障 fallback 的存在只是为了 hot cut 那天不再翻车。
3. **统一错误信封**：所有未处理异常 → `{"error_code":"INTERNAL_ERROR",
   "message","request_id"}`，未来加可观测性时直接根据 `request_id`
   索引日志。
4. **OpenAPI 为单一可信源**：`openapi.json` 手工对齐 P0 路由 + 自动化生成
   live-book / co-writer 路由类型，65 paths / 73 schemas 的覆盖面与实际
   FastAPI 路由 1:1 对应；后续改 FastAPI 时只需 `pnpm generate:gateway`。
5. **Web 侧统一客户端**：`lib/server/gateway-client.ts` 给出 Web 端调用
   Gateway 的标准姿势 — 单例 + 环境变量 + 共享类型 —，后续把 `app/api/...`
   路由从 `fetch(GATEWAY_URL+path)` 改为 `gateways.<domain>.<method>(...)`
   的成本就是改 1 行。
