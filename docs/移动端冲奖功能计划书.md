# 移动端冲奖功能计划书

更新时间：2026-06-22

## 1. 总体判断

移动端不建议继续迁移完整活书能力。活书在 Web 端更适合承载复杂阅读、编辑、块级生成和长内容组织，直接搬到移动端会增加实现成本，也容易变成体验不佳的缩小版 Web。

移动端更适合承载高频、即时、个人化的学习动作。因此本阶段应围绕一个清晰闭环建设：

```text
拍题 -> 分步骤讲解 -> 针对不懂步骤追问 AI 导师 -> 记录薄弱知识点
     -> 按遗忘曲线主动复习 -> 拍笔记沉淀个人学习资料 -> 动态精简复习
```

核心目标不是“功能多”，而是让评委看到系统具备持续辅导能力：从一次题目学习，延伸到个性化追问、学习画像、主动复习和笔记整理。

## 2. 阶段目标

### 阶段 P0：拍题步骤追问闭环

目标：让学生在拍题讲解中，对某一步长按后直接跳转 AI 导师继续追问。

价值：

- 把拍题从“生成答案”升级为“可继续辅导”。
- 移动端交互自然，展示效果直接。
- 与现有拍题页、AI 导师页衔接成本较低。

任务：

| 状态 | 任务 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 已完成 | 步骤卡长按菜单 | 在拍题结果的每个解题步骤上支持长按，并提供显式“追问这一步”按钮 | 长按某一步出现操作菜单，展开步骤后可直接点追问 |
| 已完成 | 追问上下文组装 | 组装题图、题干、jobId、stepId、步骤标题、步骤讲解 | 跳转 AI 导师时通过本地上下文 id 携带完整上下文 |
| 已完成 | AI 导师自动首问 | 进入 AI 导师后自动生成“围绕这一步解释”的上下文提示 | AI 导师自动创建追问会话并发送聚焦当前步骤的首问 |
| 已完成 | 步骤追问会话标记 | 会话标题或 metadata 标记来自某道题的某一步 | 新会话标题为“追问：步骤标题” |
| 已完成 | 学习事件记录 | 记录 `problem_step_questioned` 事件 | 触发追问时 best-effort 写入学习事件 |

已实现交互：

- 长按步骤后弹出：
  - 追问这一步
  - 换种讲法
  - 生成类似题
- 展开步骤后也提供显式“追问这一步”按钮，降低比赛演示误触风险。

风险：

- 如果步骤内容质量不稳定，追问体验会被上游拖累。
- AI 导师可能重新解整题，需要 prompt 明确限制为“只解释当前步骤”。
- 后续若要做精细知识追踪，需要步骤数据中包含知识点或推理标签。

## 3. 阶段 P1：基于遗忘曲线的主动复习推送

目标：AI 导师根据知识点熟练度、上次练习时间和遗忘曲线，主动向学生推送复习资料。

价值：

- 让 AI 导师从“被动答疑”升级为“主动教学”。
- 能展示长期陪伴和个性化学习路径。
- 可以复用已有知识追踪、诊断测评和通知能力。

任务：

| 状态 | 任务 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 已完成 | 复习调度模型 | 根据 mastery、attempts、last_practiced_at 计算 next_review_at | 每个知识点能得到下次复习时间 |
| 已完成 | 今日复习卡 | 生成 1-3 个今日应复习知识点 | 首页或通知页展示今日复习内容 |
| 进行中 | 推送通知接入 | 使用移动端通知能力提醒复习 | 到达时间后出现本地通知 |
| 已完成 | 推送内容生成 | 每条推送包含知识点、短解释、1 道检查题 | 点击推送进入 AI 导师或诊断页 |
| 已完成 | 复习结果回写 | 学生完成后更新 mastery 和 last_practiced_at | 知识状态发生变化 |

MVP 规则：

```text
mastery < 0.35  -> 1 天后复习
0.35-0.65       -> 3 天后复习
0.65-0.85       -> 7 天后复习
mastery >= 0.85 -> 14 天后复习
```

风险：

- 推送本身不是亮点，亮点是“推送内容足够个性化”。
- 只推一句提醒会显得弱，需要推具体材料。
- 本地通知适合比赛演示，生产环境仍需要后端定时任务、时区和免打扰策略。

## 4. 阶段 P2：纸质笔记电子化与动态精简

目标：学生拍自己的纸质笔记，AI 整理成电子笔记，并根据学习情况逐步压缩成复习材料。

价值：

- 贴近学生真实学习场景。
- 与普通扫描 App 的区别在于“按掌握度动态整理”。
- 能把学生自己的笔记、错题、追问、诊断数据统一成个人学习资产。

建议定位：

不要做完整“活书”，也不要追求复杂排版还原。建议先做“AI 学习笔记整理器”：

```text
拍一页笔记 -> OCR/理解 -> 结构化知识点卡片
           -> 标注掌握状态 -> 生成今日摘要
           -> 期末模式压缩成一页复习卡
```

任务：

| 状态 | 任务 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 已完成 | 笔记图片上传 | 新增笔记入口，图片随 AI 导师 fast chat 请求发送 | 能上传一张纸质笔记 |
| 已完成 | 笔记结构化提取 | 提取标题、公式、知识点、疑问点 | 返回结构化 JSON 或 Markdown |
| 进行中 | 知识点绑定 | 先用本地知识状态启发式匹配，后续再接后端资产绑定 | 每段笔记能显示关联知识点 |
| 已完成 | 掌握度分层视图 | 按已掌握、半熟、薄弱分组笔记 | 用户能只看薄弱部分 |
| 已完成 | 期末精简模式 | 根据 mastery 生成精简版复习卡 | 同一份笔记能切换完整/精简视图 |
| 待开始 | 每日整理推送 | 每天生成今日笔记摘要 | 推送中包含需要关注的笔记片段 |

展示效果建议：

- 初学阶段：保留详细解释、例题、公式推导。
- 复习阶段：隐藏已掌握细节，只保留关键词和易错点。
- 考前阶段：生成“一页速览”，重点呈现薄弱知识点。

风险：

- 手写中文、公式、图形混排 OCR 难度高。
- 如果只做 OCR，会像普通扫描软件，教育 AI 特色不明显。
- 每日整理需要足够学习数据支撑，否则会显得假。

MVP 降级方案：

- 先支持拍照 + 手动补充文字。
- 先输出结构化卡片，不做原版排版复刻。
- 先用 mock 或已有知识状态演示动态精简，再逐步接真实模型。

## 5. 推荐实施优先级

| 优先级 | 功能 | 原因 |
| --- | --- | --- |
| P0 | 长按步骤追问 AI 导师 | 成本低、闭环强、展示直接 |
| P1 | 遗忘曲线主动复习推送 | 能体现长期个性化教学 |
| P2 | 纸质笔记动态精简 | 前景强，但不确定性和范围较大 |

不建议近期投入：

- 移动端完整活书迁移。
- 复杂 AR 教学。
- 社交排行榜。
- 教师端大屏联动。

这些功能看起来扩展性强，但对当前移动端冲奖主线帮助有限，且容易稀释工程资源。

## 6. 比赛演示脚本

推荐 3 分钟演示流程：

1. 学生拍一道题。
2. 系统生成步骤讲解和可视化结果。
3. 学生长按“不懂的第 3 步”，跳转 AI 导师。
4. AI 导师带着原题和步骤上下文解释这一处。
5. 系统记录薄弱知识点，并展示掌握度变化。
6. AI 主动推送今日复习。
7. 学生拍纸质笔记，AI 整理成电子复习卡，并展示“完整笔记”和“考前精简版”的差异。

核心讲法：

> 我们不是只做拍题答疑，而是把一次不会的题，转化为长期可追踪、可复习、可压缩的个性化学习资产。

## 10. P0 性能优化记录

完成日期：2026-06-23

问题：

- 步骤追问进入 AI 导师后响应过慢，完整回答可能需要数分钟。

瓶颈判断：

- `deep_solve` 会进入 Plan -> ReAct -> Write 的多智能体解题链路，适合完整解题，不适合解释某一步。
- `deep_question` 会进入出题 coordinator，也偏重。
- 跳转 AI 导师时读取题图并转 base64，会放大请求体，并可能触发多模态/视觉链路。

优化：

- 步骤追问统一改走 `chat` capability；移动端请求体会让 Gateway 使用 `fast` 模式，跳过 agentic pipeline。
- 追问、换讲法、类似题都通过轻量 prompt 完成，不再触发完整深度解题。
- 默认不重复把原图作为附件发送给 AI 导师，改用拍题阶段已解析出的题目快照，避免每次追问都重新跑视觉模型。
- prompt 增加字数限制，避免模型生成过长回答。
- 后端 `chat` fast 通道补齐附件透传能力，后续如果需要轻量视觉补全，可以走流式直连模型，而不必回退到 `deep_solve` 多智能体链路。

架构修正：

- 不以牺牲上下文为代价换速度。步骤追问上下文扩展为“题目快照”，保留题目、当前步骤和前后推导链。
- 拍题任务已经完成一次视觉理解和解题规划，追问阶段优先复用该结构化快照。
- Gateway 的 `problem_video_generate` 任务返回结果已补齐 `problem_snapshot`：无论任务运行中还是已完成，都会尽量返回可复用的 `steps` 和整题步骤链。
- 移动端会在任务完成态、历史恢复态、本地持久化态继续保留步骤链，避免用户稍后追问时丢失上下文。
- 后续 P1 推荐接入阿里云百炼 Qwen-OCR / Qwen-VL：拍题完成后异步生成 OCR/题面结构化摘要并按 `job_id` 缓存；步骤追问只读取缓存摘要。
- 用户显式点击“重新看题图”时，再触发一次轻量视觉模型；完整重解仍走 `deep_solve`，但作为显式重模式，不阻塞普通追问。

验证方式：

- 已运行 `npm run typecheck`，通过。

待验证：

- 真机测试首 token 时间和完整回答时间。目标：普通步骤追问应在数秒内开始输出，完整回答控制在 30 秒内。
