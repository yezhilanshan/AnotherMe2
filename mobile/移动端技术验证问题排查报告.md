# AnotherMe 移动端技术验证问题排查报告

> 排查日期：2026-05-30

## 一、问题概述

在 React Native + Expo 移动端对接 Python Gateway 的技术验证过程中，遇到了以下问题：

1. Gateway 端口冲突（8081 vs Expo Metro）
2. AI 对话端点 404 Not Found
3. CORS 跨域限制
4. SSE 流式对话在移动端不可用

---

## 二、问题一：Gateway 端口冲突

### 现象

- Gateway 和 Expo Metro 都尝试使用 8081 端口
- 手机上显示连接 8080 端口（旧配置），电脑上 Gateway 实际在 8081
- Expo Go 通过 WebSocket 连接 Metro 时被 Gateway 拦截，返回 403 Forbidden

### 原因

`AnotherMe/.env.local` 中固定配置了 `ANOTHERME2_GATEWAY_BASE_URL=http://127.0.0.1:8081`，
而 `dev-all.mjs` 脚本从该 URL 解析起始端口，导致 Gateway 占用 8081，与 Expo Metro 冲突。

### 解决方案

1. 修改 `AnotherMe/.env.local`：
   ```
   ANOTHERME2_GATEWAY_BASE_URL=http://127.0.0.1:8082
   ```

2. 确认 `mobile/lib/config.ts` 中端口一致：
   ```typescript
   const GATEWAY_PORT = '8082';
   ```

3. 重启 `pnpm dev:all`，Gateway 绑定 8082，Expo Metro 使用默认 8081，不再冲突。

## 三、问题二：AI 对话端点 404

### 现象

- 手机端调用 `/v1/ai/chat` 返回 404 Not Found
- 其他端点（`/healthz`、`/v1/capabilities`）正常

### 原因

`ai_chat.py` 中定义了 `create_ai_chat_router` 函数，但 `app.py` 中**既没有导入也没有注册**该路由：

```python
# app.py 缺少以下两行：
from .routes.ai_chat import create_ai_chat_router
app.include_router(create_ai_chat_router(settings))
```

### 解决方案

修改 `AnotherMe/anotherme2_engine/api_gateway/app.py`：

1. 添加导入：
   ```python
   from .routes.ai_chat import create_ai_chat_router
   ```

2. 注册路由：
   ```python
   app.include_router(create_ai_chat_router(settings))
   ```

## 四、问题三：CORS 跨域限制

### 现象

- 手机通过局域网 IP（192.168.x.x）访问 Gateway 时可能被 CORS 策略拦截
- 原配置仅允许 localhost 来源

### 原因

`app.py` 中 CORS 配置只包含 localhost：
```python
allow_origins=[
    "http://localhost:3000",
    "http://127.0.0.1:3000",
    "http://localhost:8080",
    "http://127.0.0.1:8080",
]
```

### 解决方案

在 `allow_origins` 列表中添加 `"*"` 允许所有来源（开发阶段）：

```python
allow_origins=[
    "http://localhost:3000",
    "http://127.0.0.1:3000",
    "http://localhost:8080",
    "http://127.0.0.1:8080",
    "*",
]
```

> 注意：生产环境应限制为具体域名。

## 五、问题四：SSE 流式对话在移动端不可用

### 现象

- API 测试页面的基础连接测试全部通过
- AI 对话页面发送消息后无响应或报错

### 排查过程

1. **Gateway 端点验证**：通过 `curl` 直接测试 `/v1/ai/chat`，SSE 流正常返回数据
   ```
   data: {"type": "agent_start", "data": {...}}
   data: {"type": "thinking", "data": {...}}
   data: {"type": "text_delta", "data": {...}}
   data: {"type": "done", "data": {...}}
   ```

2. **问题定位**：React Native 环境中 `fetch` 的 `response.body.getReader()` 行为与浏览器不同
   - `response.body` 可能为 `undefined`
   - 即使存在，Streaming read 可能不工作
   - `react-native-sse` 库的 POST 请求支持也可能有兼容性问题

### 解决方案

重写 `mobile/lib/streaming.ts`，采用多层降级策略：

```typescript
export async function streamChatWithFetch(options: StreamChatOptions): Promise<void> {
  // 1. 优先尝试 fetch + ReadableStream 流式读取
  const reader = response.body?.getReader?.();
  if (reader) {
    // 流式逐块读取...
  }

  // 2. 降级：response.text() 一次性读取全部响应
  const text = await response.text();
  // 解析 SSE 数据行...
}
```

关键改进：
- 使用 `response.body?.getReader?.()`（可选链）避免 undefined 报错
- 添加 `response.text()` 降级方案
- 每个步骤都有完善的错误捕获和 `onError` 回调
- 添加详细的 `console.log` 日志便于调试

同时简化 `mobile/lib/store.ts`：
- 移除复杂的自动降级链（XHR → fetch → react-native-sse）
- 直接调用 `streamChatWithFetch`
- 确保所有错误都通过 `onError` 传递到 UI 显示
